# 可选维护索引

本资源仅在用户要求自动影响分析或已有项目采用维护索引时加载，不是默认交付，也不是文档完成的前提。默认主文档的证据附录足够；正文不需要 SC / DP / RI / CAP / MOD / ARCH / DD / E 编号、锚点矩阵或 traceability.yaml。

## 默认使用的证据附录

按正文主题集中记录“具体结论、源码文件和符号及行号、源码版本／快照、状态与限制”。现场来源补充环境、时间和程序版本。相同来源可支持多条明确结论，不能只给文件名让读者自己猜；附录不能替代正文解释。

## 确有维护需要时

可另行维护以下简化 YAML，也可沿用项目既有索引，不必迁移所有编号。下列仅为格式，不是事实：

```yaml
baseline: "<提交或快照>"
relations:
  - scenario: "<场景自然名称>"
    deployment: "<部署方式及条件>"
    program: "<运行程序与版本>"
    configuration: "<影响该路径的配置条件；无则不适用>"
    module: "<模块名称>"
    architecture_section: "<主文档架构小节>"
    design_section: "<主文档详细设计小节>"
    source:
      path: "<源码相对路径>"
      symbol: "<符号>"
      lines: "<位置>"
    limitation: "<限制或现场未知>"
```

场景和部署允许多对多，为各具体绑定记录关系。已有稳定 ID 可继续使用，但不向面向读者的正文传播。只在启用该索引时检查关系和定位有效、新旧版本匹配、删除对象未留下悬空引用。索引完备仍不能证明文档内容充分。
