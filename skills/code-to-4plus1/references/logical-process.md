# 逻辑与进程视图

## 逻辑视图

从场景和实现解释能力、领域对象、职责边界及关系。用真实名称说明能力与模块的对应，不强制 CAP / MOD 编号；不能把目录或服务类直接当作业务能力。纯技术模块如实说明技术职责，不虚构业务意义。

关键对象说明创建、修改、读取和结束的时机，状态变化的条件及影响。职责图、对象关系图或状态图应配文字解释，展示这些对象和能力如何共同完成场景；不能只是对象名列表。共享规则在这里归纳，场景差异要明确。

## 进程视图

从启动入口解释进程、线程、事件循环和任务如何创建、调度、通信、结束及释放资源。展开同步／异步边界、队列生产消费、事务、锁、重试、幂等与故障传播，以实际机制为准。

逻辑调用、线程切换和跨进程通信分开；异步语法不证明独立进程，事务注解不保证所有调用都生效。动态绑定和框架边界无法解析时说明限制。

使用场景章节一致的运行单元名称。具体节点、实例分布及现场网络随场景解释，不能独立拆出物理现状页；这里讲清机制与部署差异的影响。代码定位集中附录，正文不要求 E 编号或索引。读者忽略链接也应能理解组件如何协作、在哪里并发、哪里等待、失败如何传播。
