# 逻辑与进程视图

## 逻辑视图

从场景、业务规则和实现归纳能力、领域对象、职责边界及关系。能力使用 CAP-*，模块使用 MOD-*。能力不等于目录或服务类；标明能力与工程模块的多对多关系。领域模型根据实际状态、数据操作和约束建立，不将所有 DTO 自动当作领域对象。

输出能力与职责图、核心对象／状态关系、关键约束、场景索引与证据。纯技术职责可保留，不为每个工具模块虚构业务含义。相同能力在不同场景有差异时明确适用条件。

## 进程视图

从启动入口和运行框架识别进程、线程、事件循环、工作任务及生命周期。追踪同步调用、网络通信、IPC、消息生产消费、调度、事务、锁、重试、幂等和关闭释放。

区分逻辑调用、线程切换与跨进程通信；异步语法不证明独立进程，事务注解需检查调用方式、边界和框架条件。未解析框架或动态绑定时记录限制。

输出运行单元图、通信机制、并发与一致性、资源生命周期及故障传播。使用场景页的 RI-* 标识；共性机制统一描述，各场景和部署变体引用并说明差异。具体节点、实例分布与现场网络始终在场景与物理视图中维护，不独立拆出物理现状页面。

两种视图的关键关系均引用 E-*；尚未确认的业务解释和运行条件按证据规则标记。
