# 源码发现

1. 读取目标仓库规则和现有登记资料，确认范围、基线、读者、输出位置及人工维护内容；排除依赖缓存、构建产物和无关生成代码，记录确有必要读取的生成代码。
2. 先列目录、工程清单、依赖及锁文件、构建与启动声明，识别第一方模块和可执行程序。登记声明版本与实际版本的差别。
3. 寻找 HTTP/RPC 路由、CLI、GUI 事件、定时任务、消息消费和后台启动入口，检查入口是否注册及启用条件。不能只从用户接口归纳全部能力。
4. 追踪入口到业务编排、数据读写、外部调用和输出，收集配置读取及条件分支、持久状态与异常出口。
5. 建立模块和能力清单，标记已详读、仅发现、排除与未知。抽样分析不得写成全库覆盖。
6. 有现场资料时按场景关联代码；没有时根据入口和功能形成候选场景，列出最小待确认问题：使用目标、实际程序版本、部署方式、功能配置与外部依赖。

先完成有依据的内容，不因没有现场资料停止源码分析。每次只读取当前问题所需代码及邻近调用上下文；必要时扩大到调用方、实现绑定和配置覆盖链。

分析阶段的中间清单：程序入口、模块职责、能力、外部依赖、配置项、部署线索、候选场景、覆盖缺口。所有“部署线索”默认只是声明，直到与现场资料建立对应。这些清单不是最终文档内容上限；成文前必须追踪关键实现，完整解释过程、规则、状态和异常，不能将发现清单原样当作架构与详细设计交付。
