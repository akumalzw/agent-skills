# 质量门槛

先检查人能否读懂，再检查结构和出处。结果可为通过、失败、现场待确认或不适用，不能把结构检查当内容验证。

## 阅读检查：交付前必做

暂时忽略附录、代码链接和其他文档，由写作者通读，复杂修订可请独立审阅者检查：

- 是否能说清系统处理什么、入口和结果是什么、主要组件如何协作？
- 每个关键场景是否能从部署条件一路读到实际处理、结果和重要异常，不需要先理解维护编号？
- 每个范围内模块是否同时有实质架构说明与详细设计，解释具体输入、规则、分支、数据变化及失败影响？
- 是否解释实际存在的配置、并发、事务和资源机制，而非只写“支持、负责、保证”？
- 图表是否有文字解读，关键语义是否已写在正文，不依赖点击源码？

任一项不能回答时，补读实现并扩写。只有标题、目录、函数清单、引用矩阵或每节一两句的复杂模块均不通过。没有凑字数指标；判断依据是具体机制是否讲明，不以页数、引用数或图数计分。

## 交付组织

- 默认一份完整主文档，四类视图作为章节，证据集中附录；未强制额外页面、YAML 或关联表。
- 场景与物理合并；开发同时包含架构说明和详细设计。
- 明确要求或存在发布限制而分卷时，每卷有完整上下文和主题叙述，不能把一句话页面互相引用当完成。
- 基线、范围、未覆盖、现场未知写清；不复制空模板或保留未填占位。

## 真实性与维护

- 关键结论在附录有可定位依据，工作区改动没有冒用 HEAD 永久链接。
- 架构接口与实现一致；场景中的程序、配置、路径和行为吻合，图文名称一致。
- 声明、现场确认、推断、未知及冲突明确；规范、建议、现状不混写。
- 现场验证具备环境、时间和版本；未运行测试、构建和渲染时明确未验证。
- 实际链接可达；只有启用维护索引时才检查其编号和关系，缺少可选索引不构成不合格。
- 无秘密、敏感原文及覆盖人工修改；未发布不得称为上线。

## 完成状态

正文充分且源码说明检查完成，现场资料缺失：交付“源码说明已完成，现场部署待确认”。正文不足、缺层或关键结论无依据：文档未完成，继续修复可处理项，不以未知清单代替正文。实际未分析的模块和场景不得称覆盖。

## Skill 包验证边界

元数据、资源和链接检查仅证明文件包结构。还需审阅指南之间有无冲突，并用实际可读正文验证模板方向。示例只说明其覆盖范围，不代表真实目标项目试用已通过。独立审阅应核对事实与可读性，而非只看章节齐全。
