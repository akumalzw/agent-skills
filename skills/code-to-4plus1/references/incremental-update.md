# 增量维护

源码变化先比较版本和实际差异，追踪接口、实现、配置及调用方。现场变化记录场景、环境、部署方式、时间、程序版本与有效配置。文档纠正核对依据，不将旧说明自动当事实。

默认按主文档章节、模块名称和附录源码定位分析影响，不依赖维护索引。有已建立的索引时辅助使用；不能因为没有编号矩阵而中断更新。公共接口、配置覆盖、共享机制和启动入口的改变都要扩展到相关场景，不能只改文件名对应的段落。

现场与源码版本不一致时分别保留，不强行绑定。新部署方式在相应场景正文中解释适用条件、程序分布、配置和行为差异；必要时增加完整场景小节，不默认创建独立页面。

1. 读取现有正文及人工修改，确认实际变更，不覆盖未理解内容。
2. 更新架构说明与详细设计，使当前正文反映新实现，不仅追加变更日志。
3. 同步场景中的部署、配置、执行路径和异常，再检查逻辑与进程机制。
4. 更新附录定位、版本和限制；旧现场验证不自动适用于新版本。
5. 修复实际存在的引用；已有可选编号需保持兼容，但不在正文新增编号负担。
6. 再次执行脱离引用阅读检查，消除因增量补丁产生的重复、矛盾、碎片和“详见”替代正文。

无法判断影响时扩大分析范围或说明具体限制。报告变化、覆盖与待重新验证事项，不把更新记录当正文替代品。
