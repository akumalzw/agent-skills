# 增量维护

## 输入变化

- 源码变化：比较新旧基线和工作区差异，解析符号、契约、配置与调用关系变化。
- 现场变化：记录场景、环境、部署变体、有效时间、程序版本、配置和证据来源。
- 文档纠正：确认纠正对象及依据，保留冲突记录，不把无依据的旧文档升级为事实。

## 影响分析

利用关联索引从变更定位 E-*、DD-*、ARCH-*、MOD-*，再扩展到能力、运行机制和相关场景部署。不能仅按文件名修改页面；公共接口、配置覆盖链、启动入口和共享实现的改变需追踪调用方。动态依赖无法确定时扩大分析并列明限制。

现场信息先确认与源码版本的对应；不匹配时分别保留版本，不将现场现象强行绑定到当前分支。新增部署方式时优先在场景中增加 DP-* 绑定，检查配置和运行机制差异，必要时创建独立场景。

## 更新步骤

1. 读取已有页面与人工维护区域，建立变化清单，不覆盖未理解的人工内容。
2. 更新受影响的架构说明及详细设计，并双向检查一致性。
3. 更新场景内的部署、配置、执行路径与代码关联，再检查逻辑和进程视图。
4. 更新证据定位、适用版本与状态。旧现场验证不自动适用于新版本，标记待重新验证。
5. 废弃对象保留替代关系，修复引用；不能静默删除仍被场景使用的证据。
6. 执行质量门槛，记录本次变化、影响范围、检查结果和待确认问题。

新增关联不得凭空补齐。无法确定影响范围时明确扩大扫描范围或报告不确定性；没有变化的新检查不需要重复执行。
