# 证据与状态

## 基线

每轮记录仓库标识、远程地址（脱敏）、分支、提交 SHA、工作区改动范围、扫描时间、分析目录、排除项。无 Git 时记录目录及本次涉及文件的内容摘要或快照标识，不虚构 SHA。有未提交改动时不能仅用 HEAD 永久链接代表实际读取内容，须关联差异或快照。

## 状态

- confirmed-source：已阅读实现直接支持结论，只证明代码行为。
- declared：配置、测试或规范表达的设定／预期，不代表已运行或现场生效。
- confirmed-field：具备现场资料或观测支持，记录环境、时间、版本、来源与确认范围。
- inferred：根据证据作出的解释，明确推理及适用条件。
- unknown：缺少证据或尚未检查；不等于不存在。
- conflict：来源不一致；保留双方版本、范围与待核查问题。

设计理由须有决策记录或明确人员说明；仅从代码归纳的理由标记推断。声明的测试与实际执行结果分开记录，已运行测试提供命令、目录、版本、结果及日志位置。

## 定位与强度

关键架构关系、部署关系、状态变化、接口契约和异常行为必须有依据，但不要求正文逐句添加证据编号。按主文档的章节主题集中在末尾附录记录具体结论、来源、版本和限制，正文先完整解释行为；读者忽略附录仍应能够理解。E-* 仅在已有维护体系或用户要求时使用，不作为默认成文要求。源码来源记录相对路径、符号及行号；远程链接使用对应提交的永久链接。配置同时追踪读取点、默认值、覆盖优先级和使用点。现场来源记录环境、时间和对应版本；不能对应版本时明确限制。必要的未知、推断和冲突用自然语言在正文说明，不必每段贴英文状态标签。

注释可能过期，依赖存在不证明使用，测试断言不证明生产行为，部署模板不证明现场部署。执行链路检查路由注册、实例绑定、分支条件和调用目标；接口声明或方法名称不能单独证明链路成立。反射、动态加载、生成代码、外部闭源依赖无法解析时标明边界。检索未命中只能表述“本次范围未发现”。

## 冲突与隐私

代码、配置、现场行为或已有文档冲突时分别呈现，不擅自用新文档覆盖现场事实。规范要求与当前实现分别标注。仅记录配置键和凭据引用，省略秘密值；示例用明确的虚构数据。现场标识按授权范围脱敏。
